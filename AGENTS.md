# Oracle Lab agent guide

## Purpose and current scope

Oracle Lab evaluates tests generated by coding agents against buggy and golden
versions of the same repository. The agent sees the buggy checkout and an ordinary
test-generation prompt, without the issue description, repair patch, or private
reference test. The current implementation supports individual Python/pytest
tasks from SWE-bench and SWE-rebench V2, using each dataset's prepared repository
images.

Read these references before changing related behavior:

- `README.md` for the user workflow and CLI overview.
- `docs/configuration.md` for the complete YAML interface.
- `docs/results.md` for the run artifact contracts.
- `docs/judging.md` for the LLM judge and the human review page.
- `docs/human-review.md` for sharing review sets with raters.
- `docs/containers.md` for Docker transport and image builds.

## Architecture and trust boundaries

The host orchestrator resolves an instance, prepares a runtime image, names the
code a localized run targets, performs a private reference-pair check, launches
the agent in a buggy generation container, captures new tests, and evaluates the
same frozen artifact in fresh buggy and golden containers. A configured run then
judges that submission in a separate privileged container that may see the
private evidence.

Preserve these boundaries:

- Never expose `instance.json`, the golden repair, the reference test patch, or
  private evaluation results to the generation agent. The judge deliberately
  receives all of it; keep that bundle in the judge modules rather than relaxing
  `Repository.prepare()` or the generation upload policy.
- The localized target (`inputs/target.json`) is the one thing derived from the
  golden repair that the agent sees. It names existing files, functions, and
  classes only; never add patch text, changed lines, or expected behavior to it.
- Human raters see the LLM judge's output and all of its evidence, but never
  another rater's review.
- Never mount the host Docker socket or complete host run directory into the
  generation container.
- Run agents as the non-root `oracle` user. Docker is the isolation boundary for
  agent permission-bypass flags.
- Keep every disposable profile on Docker's ordinary outbound bridge network, so
  reference and final evaluation match the generation environment.
- Evaluate only captured new regular files under `task.generated_dir`.
- Record edits outside the generated directory as forbidden changes and mark the
  result diagnostic-only. Do not silently discard or normalize them.
- Evaluate identical, checksum-verified generated files on both code versions.
- Keep credentials out of configuration, command arguments, logs, reports, and
  tests. Pass only the selected credential through the process environment and
  redact it from captured agent output.

## Code layout

The pipeline stages run in this order, and each is one module or package that
`run.py` calls once:

- `src/oracle_lab/instance/`: resolve — dataset record, runtime, and private
  ground truth.
- `src/oracle_lab/container/images.py`: build — the prepared runtime image.
- `src/oracle_lab/localization/`: localize — for localized runs, the target
  named in the prompt. `patches.py` applies the golden patch on the host and
  `target.py` compares the buggy and repaired syntax trees.
- `src/oracle_lab/evaluation/`: reference and evaluate — paired execution in
  `__init__.py` and outcome pairing in `outcomes.py`.
- `src/oracle_lab/generation.py`: generate — one agent turn in a buggy
  checkout, then capture and freeze the submission.
- `src/oracle_lab/judge/`: judge — `contracts.py` (every persisted judge
  contract, plus judgment parsing and saved state), `workspace.py` (building the
  privileged `/oracle-judge` bundle), and `run.py` (the LLM judge stage).
- `src/oracle_lab/report.py`: report — Markdown rendering from saved artifacts.

Supporting these:

- `src/oracle_lab/cli.py`: the command interface: `run`, `preflight`, `batch`,
  `evaluate`, `judge`, `classify`, `review`, `agreement`, and `report`.
- `src/oracle_lab/run.py`: the stage sequence and run status.
- `src/oracle_lab/preflight.py`: `preflight`, which runs the stages before
  generation plus an environment check, without calling a model.
- `src/oracle_lab/batch/`: sequential batch execution and its summary.
- `src/oracle_lab/classification/`: standalone task classification, run with
  `classify` outside the run stages. Its `contracts.py`, `workspace.py`, and
  `run.py` mirror `judge/`. Reports read the newest matching attempt.
- `src/oracle_lab/review/`: human review of the LLM judges.
  - `contracts.py`: the rating scale, the review, its provenance, and the
    agreement report.
  - `targets.py`: `JudgmentTarget` and `ClassificationTarget`, which hold
    everything particular to each stage, and finding them on disk.
  - `sources.py`: the judge's buggy and golden views, rebuilt from a shallow Git
    fetch.
  - `store.py`: saving and reading reviews.
  - `agreement.py`: inter-rater agreement and judge quality.
- `src/oracle_lab/web/`: the local review page. `session.py` answers what the
  page asks, `server.py` serves it over HTTP on `127.0.0.1`, and `static/` is the
  page itself: one ES module per view, with pinned libraries in `static/vendor/`.
  It holds no review logic of its own.
- `src/oracle_lab/spend.py`: the OpenRouter key spend measured around a run's
  model stages, saved as `cost.json`.
- `src/oracle_lab/config.py`, `paths.py`, `results.py`: the input contract, the
  artifact layout, and the result contracts.
- `src/oracle_lab/repository.py`: the repository checkout inside a sandbox,
  shared by generation and evaluation.
- `src/oracle_lab/container/`, `harnesses/`: Docker transport and the agent CLI
  adapters. Within `container/`, `helpers/` holds the scripts copied into images and
  `docker/` the checked-in harness/runtime Dockerfiles.
- `src/oracle_lab/io.py`: JSON reading/writing and hashing.

- `configs/`: runnable example configurations.
- `prompts/agent/`: public generation prompts; `prompts/judge/`: rating rubrics.
  Both are delivered to a model, so they live in one tree.

Keep harness-specific behavior in its adapter, including command construction,
trace parsing, stopping-policy flags, and any container path a CLI writes to.
Callers describe a turn; adapters decide how to run it. Add shared behavior only
after both harnesses need the same contract.

Persisted artifacts are not versioned. Strict models reject anything they do not
describe, so a contract change makes stale artifacts fail loudly rather than be
half-interpreted. Change the contract and the fixtures together; do not add
compatibility shims for artifacts produced by an earlier revision.

## Development workflow

Use uv for the host Python environment:

```sh
uv sync --extra dataset --extra dev
uv run oracle-lab --help
```

Use `rg` for searches. Make focused edits and preserve unrelated work in the
working tree. Do not commit generated `runs/`, `.env`, caches, or credentials.

When adding or changing configuration fields:

1. Add the field and validation in `src/oracle_lab/config.py`.
2. Update relevant sample files in `configs/`.
3. Document the field in `docs/configuration.md`.
4. Add a focused configuration or behavior test.

When adding or changing persisted artifacts:

1. Keep raw evidence alongside normalized summaries.
2. Make incomplete states explicit; never treat missing output as success.
3. Update `docs/results.md` and report links when applicable.
4. Add tests for parsing, failure behavior, integrity, or rendering.

Model every persisted contract in `results.py`, `judge/contracts.py`,
`classification/contracts.py`, or `review/contracts.py`, and validate it where
container output enters the host, not at each reader. Test fixtures for these
artifacts belong in `tests/fixtures.py` so one schema change breaks in one place.

Two conventions keep call sites predictable: `RunPaths` is the handle for a run,
and only `cli.py` builds one from a user-supplied path; container-side logic is a
module in `container/helpers/`, never a Python string passed to `python -c`.

Use Mermaid for diagrams embedded in Markdown. Use D2 for dedicated standalone
diagram files unless the user requests another format.

## Validation

Run the local suite for code changes:

```sh
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
```

Local tests must not require Docker, network access, or real credentials. Mock
credential values must never resemble or contain a real secret.

Docker integration checks require a prior run with its runtime image still
available, but do not call a model:

```sh
ORACLE_LAB_SMOKE_RUN=runs/<run-id> uv run pytest -q -m docker
```

Run a paid or quota-limited model smoke test only when the user authorizes it.
Prefer the small smoke prompt, a short wall-time limit, and a provider budget
where the harness supports one. A successful pipeline does not require the generated tests
to detect the hidden bug.

## Result semantics

Only completed binary test executions on both versions enter the four matrix
cells. Preserve skips, xfails, xpasses, setup or collection errors, timeouts,
crashes, missing IDs, and other incomplete outcomes separately. A failing test is
a benchmark result, not an infrastructure failure. Empty submissions are
`no_tests`, not successful executions.

Matrix detection and judge verdicts answer different questions. Never substitute
one for the other, and never let a judge failure change generation or evaluation
completion state.

`fail_on_buggy_pass_on_golden` is the expected distinguishing direction.
`pass_on_both` only says the test did not distinguish the pair; it does not prove
that the oracle is incorrect.

## Current limitations

Do not accidentally present deferred features as implemented. Current gaps
include arbitrary repository environment construction, repositories whose tests
do not run under pytest (such as Django and SymPy), concurrent batch execution,
internet-use auditing, and reconstruction of discarded agent tests. Add these
deliberately, as their own changes, rather than as one-off behavior in the
existing pipeline.
